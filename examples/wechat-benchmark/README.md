# WeChat miniprogram benchmark

End-to-end perf comparison of x-markdown-mini against the mainstream WeChat-runtime
markdown libraries (`mp-html`, `towxml`) inside a real WeChat miniprogram.

**This is the marketing-grade benchmark.** For the CI-gated Node-side regression
test see [`benchmark/`](../../benchmark) in the repo root.

## Why this exists

The miniprogram-specific libraries can't run in Node — they depend on `wx`
globals, WXML output, and `setData`. To honestly compare against them we have
to run *inside* a miniprogram. This project is that runner.

## What it measures

For each library, we record the wall time between **"user taps Run"** and the
library's render-ready signal:

| Library | Ready signal |
|---|---|
| x-markdown-mini | `bind:rendercomplete` (after the lib's `onRenderComplete` fires) |
| mp-html | `bindready` |
| towxml | `setData` callback after the synchronous `app.towxml(content, 'markdown')` parse |

The numbers include parse + JS-side tree construction + the `setData` round
trip. The downstream native rich-text layout/paint is *not* in this window — it
happens after `setData` resolves and isn't observable from JS in any of the
three libraries.

## How to run

1. **Build the lib first** (so the miniprogram entry under
   `dist/miniprogram_dist/` exists):

   ```bash
   cd <repo-root>
   npm run build
   ```

2. **Install miniprogram-side dependencies**:

   ```bash
   cd examples/wechat-benchmark
   npm install
   ```

   This pulls in `mp-html`, `towxml`, and a `file:`-linked
   `@ant-design/x-markdown-mini` from the parent repo.

3. **Open in WeChat DevTools**:
   - File → Open → pick `examples/wechat-benchmark/`
   - The included `project.config.json` uses `appid: "touristappid"` so no
     account/login is required.

4. **Build the npm bundle** (DevTools menu): Tools → Build npm.
   This generates `miniprogram_npm/` which holds the actual code the
   miniprogram resolves at runtime.

5. **Compile + preview**. The page auto-loads with the `ai-chat-long.md` sample
   pre-selected; tap **重新跑** to time all three libraries on it. Tap
   **切换语料** to cycle through the bundled samples.

## Bundled samples

Generated by `scripts/sync-samples.mjs` from the Node-side corpus, so the
miniprogram test data stays in sync with the CI bench:

- `ai-chat-long.md` — long LLM-style document (~8 KB, the headline scenario)
- `block-tables.md` — table-heavy block parsing
- `block-list-nested.md` — deeply nested lists
- `lorem1.txt` — long paragraphs of inline content

Refresh after editing the source corpus:

```bash
node scripts/sync-samples.mjs
```

## What's intentionally not included

- **wemark** — author-declared unmaintained, last update years ago. Mentioned
  in the README so reviewers know we considered it.
- **wxParse** — abandoned since 2020, doesn't support modern miniprogram
  toolchain.
- **Automated CI run** — running this in CI would require WeChat DevTools CLI
  + `miniprogram-automator` + login state, which is too brittle and slow for
  PR gating. This project is meant to be run manually before releases or when
  publishing performance numbers.

## Reading the numbers

- Run multiple times and eyeball the **median** — the simulator has frame-to-frame
  jitter and the first run after IDE startup is always slower.
- The "相对最快" column shows each library's ratio to the fastest in that run.
  That's the number worth quoting; absolute ms are device-dependent.
- For real-device numbers, preview to a phone and run there. Simulator ≠ device.
