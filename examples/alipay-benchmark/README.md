# Alipay miniprogram benchmark

End-to-end perf comparison of x-markdown-mini against alternatives that work
inside an Alipay miniprogram runtime.

**This is the marketing-grade benchmark.** For the CI-gated Node-side regression
test see [`benchmark/`](../../benchmark) in the repo root. For the WeChat-side
equivalent see [`examples/wechat-benchmark/`](../wechat-benchmark).

## Why this exists

Most miniprogram markdown libraries target WeChat first; the Alipay story is
much thinner. To honestly compare x-markdown-mini on Alipay we run *inside* an
Alipay miniprogram against the only two practical alternatives:

- **towxml** — a multi-platform library with Alipay support in its 2.x line.
- **marked + native `<rich-text>`** — the "no markdown library" lower bound.
  Treats markdown as a one-shot HTML conversion (`marked.parse()`) and hands
  the resulting string to Alipay's native rich-text component. Useful as the
  baseline that anyone could write without depending on a markdown library.

## What it measures

For each library, we record the wall time between **"user taps Run"** and the
library's render-ready signal:

| Library | Ready signal |
|---|---|
| x-markdown-mini | `onRenderComplete` (after the lib's `onRenderComplete` fires) |
| towxml | `setData` callback after the synchronous `app.towxml(content, 'markdown')` parse |
| marked + rich-text | `setData` callback after `marked.parse(content)` |

The numbers include parse + JS-side tree construction + the `setData` round
trip. The downstream native rich-text layout/paint is *not* in this window — it
happens after `setData` resolves and isn't observable from JS.

## How to run

1. **Build the lib first** (so the Alipay package root under `dist/` exists):

   ```bash
   cd <repo-root>
   npm run build
   ```

2. **Install miniprogram-side dependencies**:

   ```bash
   cd examples/alipay-benchmark
   npm install
   ```

   This pulls in `towxml`, `marked`, and a `file:`-linked
   `@ant-design/x-markdown-mini` from the parent repo.

3. **Open in Alipay DevTools (小程序开发者工具)**:
   - File → Open → pick `examples/alipay-benchmark/`
   - The included `mini.project.json` uses `compileType: "mini"` and
     `component2: true`.

4. **Build npm**: in Alipay DevTools, run the npm build step (工具 → 构建 npm).
   This generates `miniprogram_npm/` which holds the actual code the
   miniprogram resolves at runtime.

5. **Compile + preview**. The page auto-loads with the `ai-chat-long.md` sample
   pre-selected; tap **重新跑** to time all three contenders on it. Tap
   **切换语料** to cycle through the bundled samples.

## Known caveats

- **towxml on Alipay**: towxml 2.x ships an Alipay build, but the component
  registration path (`towxml/towxml`) and prop name (`nodes`) may need
  adjustment if upstream changes. If the towxml panel renders empty or the
  compiler complains, check `node_modules/towxml/` for the current Alipay
  entry and update `pages/bench/bench.json` accordingly.
- **marked version**: pinned to `^18` to match the main library. If `marked`
  trips the Alipay compiler with ESM-only syntax, downgrade to `^4` (last
  CJS-first major).

## Bundled samples

Generated by `scripts/sync-samples.mjs` from the Node-side corpus, so the
miniprogram test data stays in sync with the CI bench:

- `ai-chat-long.md` — long LLM-style document (~8 KB, the headline scenario)
- `block-tables.md` — table-heavy block parsing
- `block-list-nested.md` — deeply nested lists
- `lorem1.txt` — long paragraphs of inline content

Refresh after editing the source corpus:

```bash
node scripts/sync-samples.mjs
```

## What's intentionally not included

- **A WeChat-port of `mp-html`** — `mp-html` is WeChat-only and has no Alipay
  build, so it has no place in the Alipay comparison.
- **Automated CI run** — running this in CI would require Alipay DevTools CLI
  + login state, which is too brittle and slow for PR gating. This project is
  meant to be run manually before releases or when publishing performance
  numbers.

## Reading the numbers

- Run multiple times and eyeball the **median** — the simulator has frame-to-frame
  jitter and the first run after IDE startup is always slower.
- The "相对最快" column shows each library's ratio to the fastest in that run.
  That's the number worth quoting; absolute ms are device-dependent.
- For real-device numbers, preview to a phone and run there. Simulator ≠ device.
